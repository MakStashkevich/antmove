короче, с местом на mac у меня начались проблемы. приложения, их данные, xcode, бэкапы, фото, видео, музыка — всё это постепенно набралось на внутреннем диске. а потом в какой-то момент стало не хватать места уже на обычные вещи: поставить приложение, скачать игру, сделать очередную копию айфона.

покупать новый mac из-за того, что не хватило накопителя, мне вообще не хотелось. сейчас и так всё дорожает, а память особенно нужна большим ИИ-компаниям для их дата-центров. а мне не нужны были новые мощности — мне нужно было куда-то деть большие папки и продолжить работать.

я стал думать, как перенести эти папки на внешний диск так, чтобы приложения продолжали находить их по старому адресу. из этого и появился antmove.

он копирует выбранные данные на внешний диск, проверяет копию и только после этого заменяет исходную папку ссылкой. для приложения адрес остаётся прежним, а сами файлы лежат уже на внешнем диске. вот в общем и всё, что он делает.

## как это работает

механизм тут простой: на месте исходной папки появляется символическая ссылка на папку на внешнем диске. macos и приложение обращаются по прежнему пути, а диск перенаправляет их к данным.

если места снова станет мало, можно подключить другой диск и перенести туда ещё что-нибудь. звучит почти как бесконечная память, но диск, конечно, надо держать подключённым. и переносить можно только то, что antmove умеет обработать.

## что он умеет находить

- приложения из <code>/Applications</code> и <code>~/Applications</code>;
- крупные папки данных, которые можно однозначно связать с установленным приложением;
- данные xcode и инструментов apple, android sdk и avd, часть данных инструментов разработчика;
- медиатеки apple photos, файлы apple music/itunes, папки медиа и загрузок apple tv, резервные копии iphone/ipad — если macos разрешает к ним доступ;
- старые записи о переносах extender, чтобы подтянуть их в состояние и журнал antmove.

docker desktop, orbstack, colima и rancher desktop тоже могут появиться в списке. но их внутренние хранилища antmove не переносит: там виртуальные машины и базы данных, и простое перетаскивание папки может всё сломать. для них утилита только подсказывает штатный способ.

если у большой папки не получается надёжно определить владельца, она так и останется без владельца. тут лучше не гадать.

## как установить

для apple silicon нужен архив <code>arm64</code>, для intel — <code>amd64</code>. архив для своего mac скачай в [релизах antmove](https://github.com/MakStashkevich/antmove/releases).

распакуй архив и один раз запусти бинарник:

~~~sh
cd ~/Downloads/antmove
./antmove
~~~

при первом запуске он поставит команды <code>antmove</code> и короткую <code>am</code> в <code>~/.local/bin</code>. если этой папки нет в <code>PATH</code>, установщик добавит её в настройки оболочки. после этого надо открыть терминал заново.

можно запускать и без установки — прямо из распакованной папки:

~~~sh
./antmove
~~~

а если надо явно установить или починить команды, выполни:

~~~sh
./install-local.sh
~~~

### установить bash-скриптом

в проекте есть <code>install.sh</code>. он проверит macos и тип процессора, скачает последний релиз во временную папку и установит cli. пользовательские данные скрипт не сканирует и не переносит.

установить можно одной командой:

~~~sh
curl -fsSL https://raw.githubusercontent.com/MakStashkevich/antmove/main/install.sh | bash
~~~


скрипт написан на обычном bash, его можно открыть по этой же ссылке перед запуском. он только скачивает antmove и устанавливает его; файлы не сканирует и не переносит.

### установить через homebrew

~~~sh
brew tap MakStashkevich/antmove https://github.com/MakStashkevich/antmove.git
brew install antmove
~~~

Чтобы обновить потом:

~~~sh
brew upgrade antmove
~~~

Homebrew соберёт antmove из исходников и установит команды <code>antmove</code> и <code>am</code>. Go он сам поставит как зависимость для сборки.

### собрать самому

если хочешь собрать из исходников, нужен go 1.24 или новее:

~~~sh
git clone https://github.com/MakStashkevich/antmove.git
cd antmove
make build
./bin/antmove install
~~~

для готового бинарника go, swift и xcode не нужны.

### попросить ии

в репозитории лежит skill для codex, claude code, cursor и похожих помощников. подключить его можно так:

~~~sh
npx skills add MakStashkevich/antmove -a codex claude-code cursor -g -y
~~~

для codex и claude code также подготовлены плагины. файлы лежат в <code>.agents/plugins</code> и <code>plugins/antmove</code>, команды подключения — в <code>plugins/antmove/README.md</code>.

помощнику можно написать прямо так:

> установи antmove по официальной инструкции. объясни команды, поставь только утилиту и проверь через am --version. ничего не сканируй и не переноси без моей просьбы.

и это важно: просьба установить antmove не означает, что ему можно переносить файлы. сначала пусть покажет план через <code>--dry-run</code> и объяснит, что поменяется. потом уже можно решать.

## с чего начать

запусти:

~~~sh
am
~~~

откроется меню. стрелками перемещайся, enter — выбрать, пробелом отмечай элементы. подсказки клавиш всегда внизу.

язык самого интерфейса сейчас английский. документацию сделал на семи языках.

сначала просто посмотри, что найдено:

~~~sh
am scan
~~~

а потом — какие диски можно использовать:

~~~sh
am disks
~~~

на что смотреть? на формат диска, скорость, подключение и свободное место. apfs на ssd — лучший вариант. hfs+ и apfs на обычном жёстком диске тоже могут подойти, но приложения и игры будут работать медленнее. exfat, fat и неизвестные форматы получают предупреждение: могут потеряться метаданные macos или появиться проблемы с совместимостью.

сетевой диск, системный том, диск только для чтения или том, которого сейчас нет, выбрать нельзя.

если хочется узнать скорость, antmove временно запишет файл на 256 миб, прочитает его и удалит:

~~~sh
am disks --test "/Volumes/Рабочий SSD"
~~~

ориентиры по чтению такие:

| нагрузка | нормально | хорошо | отлично |
| --- | ---: | ---: | ---: |
| игры | 150 МБ/с | 350 МБ/с | 700 МБ/с |
| офисные приложения | 30 МБ/с | 75 МБ/с | 150 МБ/с |
| мессенджеры | 20 МБ/с | 50 МБ/с | 100 МБ/с |

## сначала посмотреть, потом переносить

я бы делал вот так:

1. подключил внешний диск и проверил его через <code>am disks</code>;
2. запустил <code>am scan</code> и посмотрел на название, размер, статус и примечание;
3. закрыл приложение, если оно запущено, и дождался бы окончания бэкапа или синхронизации;
4. выбрал бы **Move data** в меню, отметил нужное, указал диск, перечитал предупреждение и подтвердил;
5. не отключал бы диск, пока пользуюсь перенесёнными данными.

antmove не будет закрывать приложения и движки за тебя. если программа открыта, закрой её сам и запусти сканирование ещё раз.

перед настоящим переносом можно посмотреть план по id из <code>am scan</code>:

~~~sh
am move --disk "/Volumes/Рабочий SSD" --dry-run 71a29f5a1cd0
~~~

эта команда ничего не копирует и не меняет. если в плане всё понятно, тогда уже запускай перенос:

~~~sh
am move --disk "/Volumes/Рабочий SSD" --yes 71a29f5a1cd0
~~~

<code>--yes</code> нужен для переноса без меню на рекомендуемый диск. а если диск с предупреждением, надо подтвердить два раза:

~~~sh
am move --disk "/Volumes/Общий диск" --confirm-caution --confirm-caution 71a29f5a1cd0
~~~

не жми подтверждения автоматически. сначала прочитай, чем именно диск не подходит. медленный диск может испортить впечатление от игры, а файловая система — не сохранить часть метаданных macos. два подтверждения только говорят «я понял риск», а не делают диск хорошим.

дальше antmove проверит свободное место, скопирует данные через системный <code>ditto</code> во временную папку, сверит хэши и содержимое каталогов и только потом поставит ссылку на новый путь. журнал операций находится в <code>~/Library/Application Support/antmove</code>.

## отдельно про фото, музыку, фильмы и бэкапы

- **photos.** закрой photos перед переносом медиатеки <code>.photoslibrary</code>. apple рекомендует apfs или mac os extended. после переноса открой медиатеку с нового места; если используешь icloud photos, при необходимости выбери её системной. диск должен быть подключён.
- **music.** закрой music. после переноса проверь <code>Music → Settings → Files → Media Location</code>, особенно если будешь добавлять новые файлы. antmove настройки music не меняет.
- **apple tv.** тоже закрой перед переносом. загруженные фильмы могут быть защищены drm. после переноса проверь воспроизведение и не отключай диск во время просмотра. папка медиа настраивается в <code>TV → Settings → Files</code>.
- **резервные копии iphone/ipad.** стандартное место — <code>~/Library/Application Support/MobileSync/Backup</code>. дождись, пока finder закончит копирование или синхронизацию. если macos не даёт доступ, выдай приложению терминала full disk access, перезапусти его и повтори <code>am scan</code>.
- **docker.** тут только штатный путь через настройки самого движка. таскать файлы виртуальной машины или базы данных как обычную папку я бы не стал.

официальные инструкции apple: [перенос медиатеки photos](https://support.apple.com/en-ie/108345), [настройки файлов music](https://support.apple.com/en-ca/guide/music/mus69248042d/mac), [настройки apple tv](https://support.apple.com/en-gb/guide/tvapp-mac/tv0f5accea/mac), [где лежат резервные копии iphone](https://support.apple.com/en-la/108809).

## если понадобится вернуть всё обратно

сначала посмотри, что именно будет восстановлено:

~~~sh
am restore --dry-run 71a29f5a1cd0
~~~

если план нормальный, верни данные:

~~~sh
am restore --yes 71a29f5a1cd0
~~~

посмотреть историю и подключение внешнего диска можно командой:

~~~sh
am status
~~~

если перенос оборвался, подключи нужный диск и запусти:

~~~sh
am recover
~~~

а если решишь удалить antmove, команда попросит подтвердить это дважды:

~~~sh
am uninstall
~~~

удаление программы не возвращает данные назад. сначала используй <code>am restore</code> или оставь диск подключённым вместе со ссылками.

## все команды под рукой

| команда | что делает |
| --- | --- |
| <code>am</code> | открыть меню |
| <code>am install</code> | установить или восстановить команды |
| <code>am uninstall</code> | удалить antmove после двух подтверждений |
| <code>am scan</code> | найти кандидатов и показать их статус |
| <code>am disks</code> | показать диски и их пригодность |
| <code>am disks --test PATH</code> | измерить скорость чтения и записи |
| <code>am move --disk PATH [ID…]</code> | перенести выбранные элементы |
| <code>am restore [ID…]</code> | вернуть данные на исходный путь |
| <code>am status</code> | посмотреть журнал и доступность диска |
| <code>am recover</code> | продолжить восстановление после сбоя |
| <code>am migrate --dry-run</code> | посмотреть план переноса записей extender |
| <code>am migrate</code> | перенести старые записи extender |
| <code>am --help</code> | показать справку |
| <code>am --version</code> | показать версию и сведения о системе |

## если захочешь собрать проект

нужен go 1.24 или новее. на macos можно собрать для своей машины, обеих архитектур или сразу подготовить релизные архивы:

~~~sh
make build
make build-arm64
make build-amd64
make release
make test
make check
~~~

архивы появятся в <code>dist/</code>. команды <code>make test</code> и <code>make check</code> запускают тесты. я их добавил в makefile, чтобы не искать каждый раз длинные команды.

релизные бинарники сейчас не подписаны и не нотариализованы. macos может попросить вручную разрешить запуск в **Системные настройки → Конфиденциальность и безопасность**.
